**任务按原样内容字符串引用,绝不使用自动生成的 ID——不存在 "task-1"/"task-N"。在 `task` 字段中传内容文本。**

每次完成时,最早仍未关闭的任务(按阶段顺序)会自动提升为 `in_progress`。
按乱序完成阶段内的任务可能把该指针**移回**较早的阶段——这是预期行为;已完成的任务绝不会被回退。

## 操作

|`op`|必需字段|效果|
|---|---|---|
|`init`|`list: [{phase, items: string[]}]`|初始化完整列表(替换现有)|
|`init`|`items: string[]`|扁平化单阶段初始化|
|`start`|`task`|标记进行中|
|`done`|`task` 或 `phase`|标记完成|
|`drop`|`task` 或 `phase`|标记放弃|
|`block`|`task` 或 `phase`,可选 `reason`|标记**已阻塞** — 打开但等待外部输入;从停止时的未完成-todo 提醒中排除|
|`unblock`|`task` 或 `phase`|把已阻塞任务恢复到 `pending`|
|`rm`|`task` 或 `phase`(可选)|移除任务或阶段;两者都省略则清空|
|`append`|`phase`,`items: string[]`|把任务追加到 `phase`;惰性创建阶段|
|`view`|—|只读:回显列表|

## 结构
- **任务内容**:5-10 个词;做什么,而不是怎么做。唯一标识符。
- **阶段名**:短名词短语(例如 `Foundation`、`Auth`、`Verification`)。唯一标识符。绝不加 `1.`、`A)`、`Phase 1:` 前缀。

## 规则
- 完成一项任务后立即标记完成。按顺序完成阶段。
- 绝不让 todo 调用成为你轮次的唯一工具调用——把它与真实工作批量在一起:`init` 与首次读取/编辑一起,每个 `done`/`start` 与下一个动作一起。单独的 todo 轮次浪费一次往返。
- 在等待你无法行动的东西(用户决定、另一个 Agent、外部服务)?`block` 该任务(可选 `reason`)——它留在跟踪器中,但不会触发停止提醒;可再次行动时 `unblock`。如果阻塞项本身可由 Agent 行动,改为 `append` 一个解除阻塞的任务。
- 引入后保持 `task`/`phase` 字符串稳定。
- 丢失确切任务文本?`view` 会回显列表——绝不凭记忆猜。

## 何时创建列表
- 任务需要 3 个以上不同步骤
- 用户明确要求
- 用户提供了一组任务
- 中途到达新指令——先捕获再继续

<critical>
用户交给你一个多步骤计划——分阶段 todo、编号/项目符号清单,或 "N bugs/items/tasks":
- 在开始工作之前,你必须用 `init` 把**每个**条目作为独立任务放进列表。
- 全部枚举;绝不压缩成更少的任务、抽样"重要的那些"、丢弃条目,或凭记忆跟踪其余部分。
</critical>
