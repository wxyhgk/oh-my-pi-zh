通过 ast-grep 进行结构化、AST 感知的改写。用于文本替换不安全的代码改写。混合语言路径没问题:每个文件用自己的语言解析,模式只改写它能解析的文件。

- `pat` 中的元变量(`$A`、`$$$ARGS`)会替换进 `out`。
- **模式匹配 AST 结构,而不是文本。** `$NAME` = 一个节点;`$_` = 不绑定;`$$$NAME` = 零或多个。
  - 使用 `$$$NAME`,不要用 `$$NAME`(无效)。名字要大写、整个节点——像 `prefix$VAR` 这样的部分匹配会失败。
- 同一个元变量出现两次 → 必须匹配相同的代码(`$A == $A` 匹配 `x == x`,不匹配 `x == y`)。
- 改写模式必须能解析为单个 AST 节点。不能独立成节点 → 包裹:`class $_ { … }`。
- TS:容忍注解——`async function $NAME($$$ARGS): $_ { $$$BODY }`。用空 `out` 删除:`{"pat":"console.log($$$)","out":""}`。
- 1:1 替换——不拆分/合并捕获。
- 匹配会被**暂存**为提案,而不是应用:通过把一句话理由写入 `xd://resolve`(应用)或 `xd://reject`(丢弃)来定案。
- 解析问题 → 格式错误的改写,而不是干净的空操作。对于一次性文本编辑,优先用 Edit 工具。
