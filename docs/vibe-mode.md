# Vibe 模式

Vibe 模式将顶层交互式会话变成一个**导演(director)**,用于管理持久的后台 Worker 会话,而不是让它自己编辑或执行命令。导演的活动工具缩减为 `read`、可选的父级拥有的 `todo`,以及五个 Worker 控制工具。Worker 负责搜索、编辑、运行与构建;导演通过阅读被触及的文件来验证它们的说法。可用时,`todo` 只属于父级导演。

## 启用与禁用

用 `/vibe` 斜杠命令切换:

```text
/vibe                 # enter vibe mode
/vibe fix the flaky test in packages/tui   # enter and submit a first directive
/vibe                 # run again to exit
```

- 进入会激活父会话 Worker 作用域,安装 vibe 工具,将活动工具集缩减为 `read`、可选的父级拥有的 `todo` 与 vibe 工具,并注入导演指令。
- 内联提示词(`/vibe <prompt>`)进入该模式,并将该提示词作为第一条指令提交。
- 退出会恢复先前的工具集,取消在途的 Worker 轮次,终止作用域内的每个 Worker 会话,并持久化终端生命周期记录。Worker 永远不会在有意退出模式后存活。
- Vibe 模式与活动**和**暂停的计划/目标模式互斥;请先退出这些模式。
- Vibe 模式活动期间,启动、派生、移动或交接会话都会被拒绝。
- 模式开启时,状态行显示 `Vibe` 指示器。

`/vibe` 是交互式 TUI 命令。模式与 Worker 生命周期事件随父会话持久化。恢复当前模式为 `vibe` 的会话时,已完成的 Worker 会以空闲/停放会话及其子转录重新水合;被进程重启中断的轮次不会自动恢复。被显式终止或因退出模式而结束的 Worker 保持终态。

## 两个 Worker 层级

每个 Worker 都是真实的、保持存活的任执行器子 Agent,具有正常的编码工具表面与自己的持久化子转录。生成时选择一个层级:

| 层级   | 捆绑 Agent | 默认角色 | 用途                                             |
| ------ | ---------- | -------- | ------------------------------------------------ |
| `fast` | `sonic`    | `@smol`  | 机械执行、草稿、大批量工作                       |
| `good` | `task`     | `@task`  | 设计、判断决策与审查 `fast` 的输出               |

层级总是选择捆绑的 `sonic` 或 `task` 定义,而非同名的已发现自定义 Agent。模型解析其余部分与任务 Agent 路由一致:`task.agentModelOverrides.sonic` / `.task` 优先于捆绑 Agent 模型,角色别名通过 `modelRoles` 解析,以父级活动/默认模型为回退。

## Worker 控制工具

| 工具         | 输入与行为                                                                                                                                                                                                  |
| ------------ | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `vibe_spawn` | `{ cli: "fast" \| "good", prompt, name? }`。启动一个空白的 Worker,带完整、自包含的首条简报。`name` 会被净化并限制为 48 个字符;省略时生成 id。                                                             |
| `vibe_send`  | `{ session, message }`。在下一步引导流式轮次;如果存在轮次但无法引导,则自动排队下一轮次;如果空闲/停放,则立即启动下一轮次。                                                                                |
| `vibe_wait`  | `{ sessions?, timeout? }`。等待第一个被监视的轮次安定(省略时为所有在途 Worker),默认 30 秒。它会确认已安定的任务,使其结果不会送达两次。                                                                    |
| `vibe_kill`  | `{ session }`。取消在途轮次,清除排队消息,释放 Worker,并在 `history://<id>` 保留任何已初始化的转录。                                                                                                       |
| `vibe_list`  | `{}`。按生成顺序列出会话,含层级、状态、轮次/队列计数、解析后的模型与最近活动。                                                                                                                            |

生成与发送立即返回。每个 Worker 轮次结果通过异步任务管理器自动送达导演对话;长响应文本在那里做预览截断,完整输出可在 `agent://<id>` 获取。在独立工作流上并发运行 `fast` 与 `good` Worker 是常规形态。

## 作用域与失败行为

Worker id 限定在拥有它的 Agent 与父会话作用域内;来自其他作用域的 Worker 会被报告为未知且无法控制。生成需要会话的异步任务管理器。生成失败会拆除部分记录;轮次失败作为失败的任务结果自动送达,而可恢复的保持存活 Worker 返回 `idle`,等待下一次 `vibe_send`。已注册子会话无法再解析的 Worker 变为 `dead`。

## 工作流

1. 将请求拆分为独立工作流——每个工作流一个持久 Worker,以便每个都积累有用的对话上下文。
2. 用自包含的简报调用 `vibe_spawn`:文件、约束与可观察的验收标准。Worker 从空白开始,永远看不到导演的对话。
3. 在轮次进行中继续指挥其他 Worker。仅在受阻时使用 `vibe_wait`;超时的等待可以重新发出。
4. 自然使用 `vibe_send` 进行纠正与下一步。轮次中途的发送在可能时进行引导;否则自动成为 Worker 的下一轮次。
5. 结果到达时,`read` 被触及的文件,并在预览不足时检查完整输出。通过可选的父级 `todo` 核对已验证的工作。
6. 按难度路由:用 `fast` 起草,当机械执行停滞或需要判断时升级到 `good`。
7. 对已完成/卡住的 Worker 使用 `vibe_kill`。退出模式会终止整个剩余作用域。

导演对最终结果负责:Worker 完成意味着轮次安定,而非其说法正确。
